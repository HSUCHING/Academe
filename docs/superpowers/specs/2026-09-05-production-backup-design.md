# Academe 生产备份设计

日期：2026-09-05

状态：本机自动备份与首次隔离恢复演练已实施；异机复制待完成

## 目标

为当前单机 Docker Compose 部署建立可重复、可审计的本机备份机制，保护 PostgreSQL 业务数据和文件系统内容，同时保持 Academe 与 LearnHouse 上游源码完全隔离。

服务器本地备份、完整性检查、定时执行和首次非生产恢复演练已经完成。异机复制继续保留为未完成任务，待用户确定外部存储后实施。

## 边界

- 所有版本化文件位于 Academe 自建的 `deploy/backup/` 和运维文档。
- 运行时备份写入已被 Git 忽略的 `runtime-data/backups/`。
- 不修改 `apps/`、根 Dockerfile 或其他上游业务源码。
- 不读取、复制、打印或打包 `deploy/.env`。
- 不备份 Redis：当前 Redis 用于缓存和队列，权威业务数据为 PostgreSQL 与内容目录；如后续确认 Redis 含不可重建状态，再单独设计。

## 备份内容与格式

每次成功备份生成一个按 UTC 时间命名的独立目录，包含：

1. PostgreSQL custom-format dump，可供 `pg_restore` 检查和恢复。
2. `runtime-data/content/` 的 gzip tar 归档，保留相对路径与文件内容。
3. SHA-256 校验文件，覆盖数据库 dump、内容归档和元数据。
4. 不含密钥的元数据文件，记录 UTC 时间、Git commit、分支、应用镜像名以及容器健康状态。

备份先写入同一文件系统的临时目录；只有所有导出与校验都成功后才原子重命名为最终目录。失败的临时目录会保留错误状态或被安全清理，但绝不冒充成功备份。

## 执行方式

`deploy/backup/backup.sh` 由宿主机执行，并完成以下流程：

1. 使用 `flock` 防止两个备份任务同时运行。
2. 确认 Compose 服务存在且 PostgreSQL 健康。
3. 在 PostgreSQL 容器内部使用已有环境变量执行 `pg_dump`，避免宿主机解析数据库密码。
4. 通过临时只读容器挂载 content 目录并生成归档，以兼容其中由 root 持有的文件。
5. 生成元数据和 SHA-256 校验文件。
6. 调用校验脚本验证 `pg_restore --list`、归档目录清单和哈希。
7. 发布完成目录，然后只清理超过保留期且名称严格匹配 Academe 备份格式的旧目录。

脚本通过自身路径定位仓库，不依赖调用者当前工作目录。所有路径在删除前必须解析并确认位于 `runtime-data/backups/` 内，禁止宽泛递归删除。

## 备份运营策略

### 频率与恢复目标

- 自动备份：每天服务器本地时间 03:15 执行一次，并设置最长 15 分钟随机延迟。
- 变更前备份：数据库迁移、高风险部署、批量导入或数据结构调整前，额外手动执行一次并保留记录。
- 当前恢复点目标（RPO）为最多丢失 24 小时的数据；首次手工恢复演练已完成，但尚未建立自动恢复时间（RTO）承诺。
- 备份为在线逻辑备份，不主动停止应用；如未来需要数据库与文件严格一致，应另行设计短暂停写窗口。

### 保留与容量

- 本机成功备份默认保留 14 天；失败或未完成目录不得计入成功备份。
- 只有新备份校验成功后才能清理过期备份；当次失败时不得删除任何历史成功备份。
- 每周检查备份总大小和磁盘空间；可用空间低于 20% 时必须记录并处理，不得扩大删除范围掩盖问题。
- 异机存储接入后的建议策略另行批准：每日保留 30 天、每周保留 12 周、每月保留 12 个月；当前不得标记为已实施。

### 检查与演练

- 每次自动验证数据库目录、内容归档和 SHA-256；任一失败即整次失败。
- 每周确认最近成功时间、文件大小、校验状态、磁盘空间和 timer 状态。
- 每月抽取一个现有备份重新执行离线完整性校验。
- 每季度至少在非生产临时环境完成一次数据库恢复和内容解包；首次演练已于 2026-09-05 完成。
- 连续 24 小时没有成功备份时按生产故障处理，修复后补做一次手动备份。

### 调度配置

- 使用 systemd service + timer；版本化源文件放在 `deploy/backup/systemd/`。
- systemd 单元只调用仓库脚本，不保存数据库凭据。
- 安装后记录 timer 状态和下一次执行时间；本轮不通过重启服务器验证。

## 验证

实施阶段至少完成：

- Shell 静态语法检查。
- 在生产数据上执行一次在线逻辑备份；不停止服务。
- `pg_restore --list` 能读取数据库 dump。
- `tar -tzf` 能读取内容归档。
- `sha256sum --check` 全部通过。
- 备份目录不含 `.env`、Token、密码或其他配置文件。
- PostgreSQL、Redis、Academe App 在备份后继续 healthy，且重启次数不增加。
- systemd timer 已启用，下一次计划时间可查询。

首次恢复演练已将 dump 恢复到无网络、无端口的临时 PostgreSQL，并逐表比较 61 张业务表、总计 21 行；内容归档解包后的 1 个文件、17,494 字节与生产内容逐文件 SHA-256 一致。临时资源已清理，生产数据未改变。

## 失败处理与回退

- 任一步失败时脚本返回非零，不发布最终备份目录，也不清理历史成功备份。
- 日志不得包含环境变量值或数据库连接串。
- 回退时停用并删除已安装的 systemd timer/service；保留现有备份，除非用户明确要求删除。
- 删除仓库内 `deploy/backup/` 不影响正在运行的数据库和应用，但已安装 timer 必须先停用，否则会留下失效任务。

## 上游同步策略

该方案只新增 Academe 自有部署文件和文档，对上游源码冲突风险极低。若未来上游提供等价且可配置的备份方案，应先完成一次恢复对比，再迁移并删除 Academe 的重复实现。
